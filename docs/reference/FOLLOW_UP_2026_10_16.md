### ROCLINK manual (S25): useful TCP distinctions, no wrapping procedure

Emerson D301250X012, February 2024, publisher download, 542 PDF pages;
SHA-256 `9785259167e431fe8212d899851a027ffb6273f1191202710c00c17b362f1e78`.
Read the TCP discussion, §§3.7.2–3.7.3 excerpts and Internet settings, printed pp.3-8,
3-27–29, 3-32–33, 3-35 and 6-13 (PDF pages 60, 79–81, 84–85, 87, 139); credential/opt-in sections
were searched with the complete extracted document. No session-key wrapping,
credential encryption/padding or public cryptographic vectors were found in the
inspected sections or the document-wide term searches.

The TCP discussion separates a security timeout refreshed by valid messages,
a configurable inactivity timeout and TCP keep-alive probes. Those are not a
ROC800 session-key validity specification. The Internet settings also distinguish
inactivity from security timeout; no universal serial refresh rule follows.
The document excludes SRBX transmission over TCP, an applicability qualification
for the library's synthetic TCP SRBX fixtures. It also prints conflicting keep-alive
arithmetic on p.6-13, so the numerical aggregate is not a reliable new default.
[Publisher manual](https://www.emerson.com/is/content/emerson/en/final-control/documents/d301250x012.pdf).

Result: narrow DEC-2.05 using applicable vendor TCP descriptions, keep DEC-2.01/02
open, and add a DEC-9.04/SRBX channel caveat. Do not alter heartbeat defaults or
remove tested transport-independent handling on this evidence alone.
